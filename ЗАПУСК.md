# Инструкция по запуску бота

Пошагово: от нуля до работающего бота. Займёт примерно 20–30 минут, из них 10 — на Google Cloud.

---

## Что понадобится

| Что | Зачем | Где взять |
|---|---|---|
| Python 3.11 или новее | Запуск бота | [python.org](https://www.python.org/downloads/) |
| Токен бота | Связь с Telegram | [@BotFather](https://t.me/BotFather) |
| Ваш Telegram ID | Доступ в админку | [@userinfobot](https://t.me/userinfobot) |
| Google-таблица | Хранение заявок | [sheets.google.com](https://sheets.google.com) |
| Ключ сервисного аккаунта | Доступ бота к таблице | [Google Cloud Console](https://console.cloud.google.com/) |

> Google Таблица необязательна. Без неё бот работает полностью, просто заявки живут только в SQLite.

---

## Шаг 1. Создайте бота в Telegram

1. Откройте [@BotFather](https://t.me/BotFather) → отправьте `/newbot`.
2. Придумайте имя и username (username должен заканчиваться на `bot`).
3. Скопируйте токен — он выглядит так: `123456789:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`.

Токен — это пароль от бота. Не публикуйте его и не коммитьте в git.

## Шаг 2. Узнайте свой Telegram ID

Напишите [@userinfobot](https://t.me/userinfobot) — он ответит числом вроде `123456789`. Это ваш ID для `ADMIN_IDS`.

> Если администраторов несколько, перечислите ID через запятую: `123456789,987654321`.

## Шаг 3. Подготовьте компьютер

### Windows

```powershell
cd путь\к\проекту
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Если PowerShell не даёт активировать окружение, выполните один раз:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### macOS / Linux

```bash
cd путь/к/проекту
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Шаг 4. Создайте `.env`

Команды запускайте **из корня проекта**, где находится `main.py`. Проверьте текущую папку:

```powershell
Get-Location
Test-Path .\main.py
```

Вторая команда должна вернуть `True`. Если вернула `False`, перейдите в каталог проекта, например:

```powershell
cd C:\Users\111\Downloads\projects
```

Скопируйте образец и откройте `.env`:

```powershell
# Windows
Copy-Item .env.example .env
notepad .env
```

```bash
# macOS / Linux
cp .env.example .env
nano .env
```

Важно: приложение читает именно `.env`, а не `.env.example`. В `.env` заполните минимум эти три строки:

```dotenv
BOT_TOKEN=вставьте_новый_токен_от_BotFather
ADMIN_IDS=ваш_telegram_id
DATABASE_URL=sqlite+aiosqlite:///data/bot.db
```

Не оставляйте буквальные значения `PASTE_YOUR_ROTATED_BOT_TOKEN_HERE` и `YOUR_TELEGRAM_USER_ID` из шаблона — это только placeholders.

После сохранения проверьте, что файл существует:

```powershell
Test-Path .env
```

Ожидаемый результат — `True`.

Остальные переменные можно оставить как есть — они уже настроены на разумные значения.

## Шаг 5. Проверьте, что всё на месте

Запустите офлайн-тесты. Сеть и Google им не нужны:

```bash
python tests/offline_smoke_test.py
python tests/test_google_sheets.py
```

Оба должны закончиться словами «Все проверки пройдены ✅» и «Google Sheets слой работает корректно ✅».

Если так — код и зависимости в порядке. Если нет, смотрите раздел «Частые ошибки» в конце.

## Шаг 6. Запустите бота

```bash
python main.py
```

В консоли появится примерно такое:

```
INFO | bot.database.base | Схема базы данных готова
INFO | main | Бот запускается…
INFO | main | Google Таблицы не настроены ... Работаем без синхронизации.
```

Теперь откройте своего бота в Telegram, отправьте `/start` — должно появиться меню с кнопками.

Проверьте сценарий целиком: «Оставить заявку» → выберите услугу → имя → телефон → комментарий → «Отправить». Вам должно прийти «Заявка №1 отправлена», а администратору — уведомление с кнопками статусов.

**Остановка:** `Ctrl+C` в консоли.

## Шаг 7 (необязательный). Подключите Google Таблицу

Пропустите этот шаг, если таблица не нужна. Бот работает и без неё.

### 7.1. Создайте таблицу

Откройте [Google Sheets](https://sheets.google.com) → создайте пустую таблицу.

Заголовки заполнять **не нужно** — бот создаст их сам при первой заявке. Скопируйте ссылку из адресной строки, она понадобится в 7.4.

### 7.2. Создайте сервисный аккаунт

1. Откройте [Google Cloud Console](https://console.cloud.google.com/).
2. Сверху выберите проект или создайте новый (**New Project**).
3. Меню → **APIs & Services** → **Library**.
4. Найдите **Google Sheets API** → **Enable**.
5. Вернитесь в **Library** → найдите **Google Drive API** → **Enable**.

   Оба API обязательны: без Drive API бот не сможет открыть таблицу по ссылке.

6. Меню → **APIs & Services** → **Credentials**.
7. **Create Credentials** → **Service account**.
   - Имя: например `orders-bot`.
   - Роль назначать не нужно.
8. Откройте созданный аккаунт → вкладка **Keys** → **Add key** → **Create new key** → **JSON** → **Create**.

Файл скачается автоматически.

### 7.3. Положите ключ в проект

Переименуйте скачанный файл в `credentials.json` и положите **рядом с `main.py`**:

```
projects/
├── main.py
├── credentials.json   ← сюда
└── .env
```

### 7.4. Дайте боту доступ к таблице

1. Откройте `credentials.json` любым текстовым редактором.
2. Найдите строку `"client_email"` — там адрес вида `orders-bot@ваш-проект.iam.gserviceaccount.com`.
3. Скопируйте этот адрес.
4. Откройте свою Google Таблицу → кнопка **Поделиться** (Share).
5. Вставьте адрес, выберите роль **Редактор** (Editor) → **Отправить**.

> Роль «Читатель» не подойдёт: бот должен не только читать, но и писать строки.

### 7.5. Пропишите ссылку в `.env`

```dotenv
GOOGLE_SHEET_URL=https://docs.google.com/spreadsheets/d/ВАШ_ДЛИННЫЙ_ID/edit
GOOGLE_CREDENTIALS_PATH=credentials.json
```

### 7.6. Перезапустите и проверьте

```bash
python main.py
```

В логах должно появиться:

```
INFO | bot.services.google_sheets | Google Sheets: используется лист «Sheet1»
INFO | main | Google Таблицы подключены: https://docs.google.com/spreadsheets/d/...
```

Оставьте тестовую заявку — она должна появиться в таблице новой строкой. В админке (`/admin` → «Статистика») будет написано «Google Таблицы: работают».

## Шаг 8 (необязательный). Запуск в Docker

Нужен установленный Docker Desktop.

1. Убедитесь, что `.env` заполнен.
2. Если используете Google — положите `credentials.json` в корень проекта.
3. Запустите:

```bash
docker compose up -d --build
docker compose logs -f bot
```

Полезные команды:

```bash
docker compose restart    # перезапуск после правки .env
docker compose down       # остановка
docker compose logs --tail 100 bot
```

Данные сохраняются в папке `./data` и переживают пересоздание контейнера.

> **Если не нужен Google**, уберите из `docker-compose.yml` строку `- ./credentials.json:/app/credentials.json:ro`. Иначе Docker не запустится: он требует, чтобы файл существовал на хосте.

## Как пользоваться

### Клиент

| Действие | Что происходит |
|---|---|
| `/start` | Приветствие и главное меню |
| «Оставить заявку» | Пошаговый диалог из 5 шагов |
| «Услуги и цены» | Информация с кнопкой оформления |
| «Мои заявки» | Список своих заявок со статусами |
| `/cancel` | Прервать заполнение |

### Администратор

Отправьте `/admin`. Доступ есть только у ID из `ADMIN_IDS`.

| Раздел | Что делает |
|---|---|
| 📊 Статистика | Пользователи, заявки за сегодня / 7 дней / всего, разбивка по статусам |
| 🗂 Последние заявки | Список по 5 штук, карточка заявки, смена статуса |
| 📣 Рассылка | Текст или фото с подписью, предпросмотр, отчёт о доставке |
| 🔗 Ссылка на таблицу | Прямая ссылка на Google Таблицу |

При смене статуса обновляются и база, и строка в таблице, а клиенту приходит уведомление.

> Администратор должен хотя бы раз нажать **Start** у бота. Иначе Telegram не даст боту написать ему первым, и уведомления не дойдут.

## Частые ошибки

**`Не удалось прочитать конфигурацию ... BOT_TOKEN`**
Нет файла `.env` или в нём пустой токен. Скопируйте `.env.example` в `.env` и заполните.

**`Telegram отклонил BOT_TOKEN (Unauthorized)`**
Токен неверный или перевыпущен в BotFather. Скопируйте актуальный токен заново.

**`ZoneInfoNotFoundError: Europe/Moscow`**
Не установлен пакет `tzdata` (на Windows он обязателен). Выполните `pip install -r requirements.txt`.

**`Нет доступа к таблице: выдайте сервисному аккаунту роль «Редактор»`**
Забыли шаг 7.4, либо выдали роль «Читатель». Заявки при этом не теряются — они в базе.

**`Таблица или лист не найдены`**
Неверная ссылка в `GOOGLE_SHEET_URL`. Нужен формат `https://docs.google.com/spreadsheets/d/<ID>/edit`.

**`В проекте Google Cloud не включены Google Sheets API и Google Drive API`**
Вернитесь к шагу 7.2 и включите оба API.

**Заявки есть в базе, но не появляются в таблице**
Проверьте три вещи: `credentials.json` лежит рядом с `main.py`, сервисный аккаунт добавлен в «Поделиться», оба API включены.

**Админ не получает уведомления**
Он не нажимал **Start** у бота, либо его ID не указан в `ADMIN_IDS`.

**`Unclosed client session` в логах**
Не должно появляться в текущей версии. Если видите — сообщите: это баг.

## Куда что настраивать

| Что менять | Файл |
|---|---|
| Тексты, цены, названия услуг, подписи кнопок | `bot/texts.py` |
| Название компании | `BRAND` в `bot/texts.py` |
| Переменные окружения | `.env` |
| Размер страницы в админке | `ORDERS_PER_PAGE` в `.env` |
| Новые статусы заявок | `ALL_STATUSES` в `bot/database/models.py` + `STATUS_META` в `bot/texts.py` |

> В словаре `SERVICES` (`bot/texts.py`) меняйте только текст, но не ключи (`bot`, `site`, `automation`, `other`) — ключи записываются в базу.
