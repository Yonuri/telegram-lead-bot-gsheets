Инструкция по установке

Запуск Telegram-бота

От пустой папки до бота, который принимает заявки и складывает их в Google Таблицу. Восемь шагов, из них десять минут уходит на Google Cloud.

  • ≈ 25 минут
  • Python 3.11+
  • Google Таблица — по желанию
  • Windows · macOS · Linux

Что понадобится

Первые три пункта обязательны. Google нужен, только если заявки должны попадать в таблицу.

ЧтоЗачемГде взять
Python 3.11+ Среда для запуска python.org
Токен бота Связь с Telegram @BotFather
Ваш Telegram ID Доступ в админку @userinfobot
Google-таблица Хранение заявок sheets.google.com
Ключ сервисного аккаунта Доступ бота к таблице Google Cloud Console
Без Google Таблицы бот работает полностью. Заявки в этом случае хранятся только в SQLite, а админам всё равно приходят уведомления.

Восемь шагов

Шаги 7 и 8 необязательны: таблица и Docker. Их можно пропустить и вернуться позже.

  1. Создайте бота в Telegram

    1. Откройте @BotFather и отправьте /newbot.
    2. Придумайте имя и username — он должен заканчиваться на bot.
    3. Скопируйте токен вида 123456789:AAH….
    Токен — это пароль от бота. Не публикуйте его и не коммитьте в git.

  2. Узнайте свой Telegram ID

    Напишите @userinfobot — он ответит числом вроде 123456789. Это ваш ID для админки.

    Если администраторов несколько, перечислите ID через запятую:

    ADMIN_IDS=123456789,987654321

  3. Подготовьте компьютер

    Windows, в PowerShell:

    cd путь\к\проекту
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt

    macOS и Linux:

    cd путь/к/проекту
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

    Если PowerShell отказывается активировать окружение, разрешите скрипты один раз:

    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

  4. Создайте файл .env

    Скопируйте образец:

    # Windows
Copy-Item .env.example .env

# macOS / Linux
cp .env.example .env

    Заполните минимум три строки:

    BOT_TOKEN=123456789:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
ADMIN_IDS=123456789
DATABASE_URL=sqlite+aiosqlite:///data/bot.db

    Остальные переменные уже настроены — их можно не трогать.

  5. Проверьте, что всё на месте

    Запустите офлайн-тесты. Ни сеть, ни Google им не нужны:

    python tests/offline_smoke_test.py
python tests/test_google_sheets.py
    Оба должны закончиться словами «Все проверки пройдены» и «Google Sheets слой работает корректно». Если так — код и зависимости в порядке.

  6. Запустите бота

    python main.py

    В консоли появится:

    INFO | bot.database.base | Схема базы данных готова
INFO | main | Бот запускается…
INFO | main | Google Таблицы не настроены … Работаем без синхронизации.

    Откройте бота в Telegram и отправьте /start — появится меню. Пройдите сценарий целиком: «Оставить заявку» → услуга → имя → телефон → комментарий → «Отправить». Вам придёт «Заявка №1 отправлена», администратору — уведомление с кнопками статусов.

    Остановка — Ctrl+C в консоли.

  7. Подключите Google ТаблицуНеобязательно

    Пропустите шаг, если таблица не нужна.

    1. Создайте таблицу. Откройте Google Sheets и создайте пустую таблицу. Заголовки заполнять не нужно — бот создаст их сам при первой заявке.

    2. Создайте сервисный аккаунт. В Google Cloud Console:

    1. Выберите проект или создайте новый.
    2. Меню → APIs & Services → Library.
    3. Найдите Google Sheets API → Enable.
    4. Там же найдите Google Drive API → Enable.
    5. Меню → Credentials → Create Credentials → Service account. Имя, например, orders-bot, роль не нужна.
    6. Откройте аккаунт → вкладка Keys → Add key → Create new key → JSON.
    Оба API обязательны. Без Drive API бот не сможет открыть таблицу по ссылке.

    3. Положите ключ в проект. Переименуйте скачанный файл в credentials.json и положите рядом с main.py.

    4. Дайте боту доступ к таблице. В credentials.json найдите поле client_email — адрес вида orders-bot@ваш-проект.iam.gserviceaccount.com. В таблице нажмите Поделиться, вставьте этот адрес, выберите роль Редактор и отправьте.

    Роль «Читатель» не подойдёт: бот должен не только читать, но и писать строки.

    5. Пропишите ссылку в .env.

    GOOGLE_SHEET_URL=https://docs.google.com/spreadsheets/d/ВАШ_ДЛИННЫЙ_ID/edit
GOOGLE_CREDENTIALS_PATH=credentials.json

    6. Перезапустите. В логах должно появиться:

    INFO | bot.services.google_sheets | Google Sheets: используется лист «Sheet1»
INFO | main | Google Таблицы подключены: https://docs.google.com/spreadsheets/d/…

    Оставьте тестовую заявку — она появится в таблице новой строкой. В админке, в разделе «Статистика», будет написано «Google Таблицы: работают».

  8. Запуск в DockerНеобязательно

    Нужен установленный Docker Desktop.

    1. Убедитесь, что .env заполнен.
    2. Если используете Google — положите credentials.json в корень проекта.
    3. Запустите:
    docker compose up -d --build
docker compose logs -f bot

    Дальше:

    docker compose restart          # после правки .env
docker compose logs --tail 100 bot
docker compose down             # остановка

    Данные лежат в папке ./data и переживают пересоздание контейнера.

    Без Google? Уберите из docker-compose.yml строку - ./credentials.json:/app/credentials.json:ro. Иначе Docker не запустится: он требует, чтобы файл существовал на хосте.

Администратор

Команда /admin. Доступ есть только у ID из ADMIN_IDS.

РазделЧто делает
СтатистикаПользователи, заявки за сегодня, за 7 дней и всего, разбивка по статусам
Последние заявкиСписок по 5 штук, карточка заявки, смена статуса
РассылкаТекст или фото с подписью, предпросмотр, отчёт о доставке
Ссылка на таблицуПрямая ссылка на Google Таблицу
При смене статуса обновляются и база, и строка в таблице, а клиенту приходит уведомление. Администратор должен хотя бы раз нажать Start у бота — иначе Telegram не даст боту написать ему первым.

Если что-то не работает

Тексты ошибок бота совпадают с заголовками ниже — ищите по ним.

Не удалось прочитать конфигурацию … BOT_TOKEN
Нет файла .env или в нём пустой токен. Скопируйте .env.example в .env и заполните.
Telegram отклонил BOT_TOKEN (Unauthorized)
Токен неверный или перевыпущен в BotFather. Скопируйте актуальный заново.
ZoneInfoNotFoundError: Europe/Moscow
Не установлен пакет tzdata — на Windows он обязателен. Выполните pip install -r requirements.txt.
Нет доступа к таблице: выдайте роль «Редактор»
Сервисный аккаунт не добавлен в «Поделиться», либо выдана роль «Читатель». Заявки при этом не теряются — они в базе.
Таблица или лист не найдены
Неверная ссылка в GOOGLE_SHEET_URL. Нужен формат https://docs.google.com/spreadsheets/d/<ID>/edit.
В проекте Google Cloud не включены Google Sheets API и Google Drive API
Вернитесь к шагу 7 и включите оба API в Library.
Заявки есть в базе, но не появляются в таблице
Проверьте три вещи: ключ лежит рядом с main.py, сервисный аккаунт добавлен в «Поделиться», оба API включены.
Админ не получает уведомления
Он не нажимал Start у бота, либо его ID не указан в ADMIN_IDS.

Переменные окружения.env
Заявок на страницу в админкеORDERS_PER_PAGE в .env
Новые статусы заявокALL_STATUSES в bot/database/models.py и STATUS_META в bot/texts.py
В словаре SERVICES меняйте только текст, но не ключи (bot, site, automation, other) — ключи записываются в базу.

Проверка перед выкладкой — три команды, все должны пройти без ошибок:

python -m compileall -q .
python tests/offline_smoke_test.py
python tests/test_google_sheets.py
